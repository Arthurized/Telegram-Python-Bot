Projects

Twelve projects for beginners

A path from a twenty-line converter to a database-backed web service. Each project introduces one new idea and reuses everything before it.

Before you start

Four habits that decide whether you learn anything from these.

Do not follow a tutorial for the project itself. Look things up constantly, but if you follow a walkthrough of the whole build you finish with working code and no new ability. The struggle in the middle is the part that teaches.

Get an ugly version working first. One file, no functions, hard-coded values. Make it do the thing once, then clean it up. Designing before anything runs is how beginner projects die at 60% complete.

Use git from project one. Commit when something starts working, before you break it again.

Do the stretch goal. It asks you to change code you already wrote, which is what the job actually consists of.

Starter Standard library only, nothing to install, one file.

Building Several concepts at once. Expect to restructure halfway through.

Stretch Third-party packages, a virtual environment, real documentation to read.

The projects

01

Unit converter

Starter~1 hour

Convert between kilometres and miles, Celsius and Fahrenheit, kilograms and pounds. Ask what to convert, ask for the number, print the answer. Deliberately small: the first project should finish in one sitting.

Details
Teaches Functions with return values, input() always handing you a string, float() and what happens when the user types nonsense, and a dictionary as a lookup table instead of a tower of if statements.
Modules None.
Then try Loop until the user quits, surviving every bad input. Add a unit pair and count how many places you had to edit.
02

Guess the number

Starter1–2 hours

The program picks a secret number, the player guesses, it answers higher or lower. The first program whose behaviour is not a straight line from top to bottom.

Details
Teaches while loops with a condition you have to reason about, counters, comparison logic, and random. Also your first bug that is not a syntax error.
Modules random
Then try Swap roles and let the program guess by binary search. It should never need more than seven guesses for 1–100 — working out why seven is the exercise.
03

Password generator

Starter1–2 hours

Generate a strong random password to a requested length, with flags for digits and symbols. The first project where the obvious approach is wrong in a way that matters.

Details
Teaches The string module's character constants and real command-line arguments with argparse. Most importantly: use secrets, not random, which is predictable by design and unfit for anything secret.
Modules secrets, string, argparse
Then try Add a passphrase mode using random words, then work out which of your two modes is actually stronger.
04

Hangman

Starter2–3 hours

Hide a word, show it as underscores, let the player guess letters, track their lives. The first project with real state to keep straight.

Details
Teaches Sets, and why they are right for "letters already guessed". String indexing and joining to render the masked word. Keeping several pieces of state consistent — the point where you start wanting functions for their own sake.
Modules random, plus a text file of words
Then try Handle the edge cases: a repeated guess should not cost a life, and a word with the same letter twice should reveal both.
05

A to-do list that remembers

Building3–4 hours

Add tasks, list them, mark them done, delete them — and have them still be there tomorrow. The persistence is the lesson: the first program that leaves something behind when it exits.

Details
Teaches Reading and writing files, json for turning objects into text and back, and pathlib for paths that work everywhere. Plus the first design question with no right answer: what if the file does not exist, or contains nonsense?
Modules json, pathlib, argparse
Then try Make saving safe against interruption: write a temporary file and rename it over the original, so a crash cannot leave you half a file.
06

Expense analyser

Building3–4 hours

Take a CSV of transactions and report on it: total per category, biggest expenses, which month was worst. The first project that produces an answer you did not already know.

Details
Teaches The csv module and why you should not split on commas yourself. Counter and defaultdict for grouping, and sorted with a key. Plus real data cleaning: inconsistent dates, blank fields, currency symbols glued on.
Modules csv, collections, statistics, datetime, decimal
Then try Use Decimal rather than float for money and find out why — start by evaluating 0.1 + 0.2 at a prompt.
07

Markdown to HTML converter

Building4–5 hours

Read a Markdown file, write HTML. Headings, bold, italic, links, lists, code blocks — a useful subset, not the whole specification. You are writing a small translator, which is a different kind of program from everything above.

Details
Teaches Regular expressions and their limits: you will hit a point where nesting defeats a regex and you need to track state line by line. That realisation is worth more than the finished converter. Plus HTML escaping, a security lesson disguised as a formatting one.
Modules re, html, pathlib, argparse
Then try Nested lists, where every naive implementation breaks. Then write tests — text in, text out makes this the ideal first project to test.
08

Duplicate file finder

Building2–3 hours

Walk a directory tree and report files with identical contents, whatever they are named. Genuinely useful on a real photo folder, and the first project where the obvious implementation is too slow.

Details
Teaches Recursive directory walking, hashing with hashlib, and reading files in chunks rather than loading a gigabyte into memory. The real lesson is algorithmic: comparing everything with everything is quadratic, so group by size first and hash only within groups.
Modules pathlib, hashlib, collections
Then try Add a --delete flag, then think hard about it: dry run by default, never remove the last copy, always confirm.
09

Notes app with a window

Building4–6 hours

Project five with an actual interface: a list of notes on one side, an editor on the other, buttons to add and delete. tkinter ships with Python, so there is nothing to install.

Details
Teaches Event-driven programming, which inverts how your programs have worked so far: you no longer control the order of events, you register callbacks and wait. Keeping the interface in step with the underlying data is the problem every graphical application has.
Modules tkinter, tkinter.ttk, json
Then try A search box that filters as you type, and a window that resizes sensibly — harder than it sounds.
10

Weather from the command line

Stretch3–4 hours

Type a city, get the conditions and a short forecast. Your first program that talks to the internet, and the first that needs a virtual environment and an installed package.

Details
Teaches HTTP requests and status codes, digging through a JSON structure you did not design, and the fact that network calls fail. Also API keys, and why they belong in an environment variable rather than in source code that ends up in a public repository.
Modules requests (installed), os, argparse
Then try Cache responses for ten minutes, and handle every failure with a message a human would understand rather than a traceback.
11

A Telegram bot

Stretch5–7 hours

A bot that answers commands in a chat. Start with an echo, then give it something real to do. The first project other people can actually use, which changes how carefully you handle bad input.

Details
Teaches Working against a substantial third-party library and its documentation, asynchronous code, long-running processes that must not fall over, and per-user state. Also deployment: a bot on your laptop stops when you close the lid.
Modules python-telegram-bot or aiogram (installed), logging, sqlite3
Then try Add a command built from an earlier project. Whether that code was reusable tells you something about how it was written.
12

URL shortener

Stretch6–8 hours

Paste a long URL, get a short one, and visiting it redirects. A page listing your links with hit counts. A complete application — web layer, database, interface — and a reasonable thing to show someone.

Details
Teaches How a web framework maps URLs to functions, GET versus POST, redirects and status codes, and templates. Plus SQL and parameterised queries, because this is where you learn what SQL injection is by deliberately not writing it.
Modules fastapi or flask (installed), sqlite3
Then try Reject anything that is not http or https, add rate limiting, then deploy it and watch the access log. The first thing a public URL attracts is automated probes.

What to do next

You will have written something in every major shape a Python program takes: script, file-processor, data analysis, desktop application, API client, long-running service, web app.

Pick a direction and go deep. Data analysis, web backends, automation, or machine learning. All four reuse everything above.

Read code better than yours. Pick a small, well-regarded package you have used and read it — not to learn what it does, but to see how people structure Python when strangers will maintain it.

Go back to project one and rewrite it. An hour's work, and the clearest possible measure of what you picked up.
