Strengths and limitations

Every language is a set of trade-offs. Knowing Python's makes it easier to tell which problems to bring to it.

What it does well

Being read. Significant indentation means badly formatted Python does not compile, so almost all Python in the world has a similar shape. Code you have never seen tends to be legible on the first pass, which matters more than it sounds: most programming time is spent reading.

Gluing other things together. Python is a comfortable driver's seat for software written in faster languages. NumPy, pandas, PyTorch and SciPy are mostly C, C++, Fortran and CUDA underneath; Python is the layer you actually type in. When people say Python is fast enough for numerical work, this is what they mean.

Short programs that do real work. The standard library ships with HTTP, JSON, CSV, SQLite, zip archives, dates, subprocesses, argument parsing, unit testing and e-mail. A useful tool is often fifty lines and no dependencies.

Being learnable. Thirty-five keywords, no type declarations required, no build step, and an interactive prompt that evaluates as you type. You can be productive before you understand how any of it works.

What it does badly

Tight CPU-bound loops in pure Python. An arithmetic loop in Python can run one to two orders of magnitude slower than the same loop in C. The fix is nearly always to stop writing the loop in Python and hand the array to a library that loops in C, not to micro-optimise the Python.

Hard real-time and tight memory budgets. Garbage collection pauses when it likes, and every integer is a heap object with a header. Microcontrollers and audio callbacks want a language you can reason about to the byte.

Shipping to someone else's machine. There is no single answer to "send me the program." Packaging a Python application for users who do not already have Python is a real project, which is why so much Python runs on servers and in notebooks instead of on desktops.

Catching your mistakes before you run it. Names are resolved at runtime, so a typo in a rarely taken branch waits patiently for production. Type hints and a checker recover much of this, but they are optional and bolted on, not part of the language's guarantees.

Where to learn Python

All of these are free to read in a browser, ordered by experience level rather than by quality.

  • Automate the Boring Stuff with Python automatetheboringstuff.com

    The best first book if you have never programmed. Al Sweigart teaches the language through chores — renaming files, filling spreadsheets, scraping pages — so you are solving recognisable problems by chapter three. Readable free online.

  • The Python Tutorial docs.python.org

    The official walkthrough. Dense and slightly dry, but correct and complete, and short enough to finish in a weekend. Start here instead if you already program in another language — it will not waste your time explaining what a variable is.

  • Think Python greenteapress.com

    Allen Downey's computer-science-flavoured introduction. Where Automate teaches tasks, this teaches concepts — recursion, data structures, algorithmic thinking — and is the better choice if you want the theory alongside.

  • The Standard Library Reference docs.python.org

    Not a tutorial, and not meant to be read front to back. Skim the module index once so you know what exists; the habit of checking here before installing a package will save you a surprising number of dependencies.

  • Real Python realpython.com

    Long, careful tutorials on single topics, which is exactly what you want for the things that do not fit in a reference entry — decorators, async, packaging, virtual environments. A good portion is free; some is behind a subscription.

  • Exercism — Python track exercism.org

    Small exercises with automated tests and, unusually, review from a human mentor. The fastest way to stop writing Python that works but reads like the language you learned before it.

  • PEP 8 — Style Guide for Python Code peps.python.org

    The conventions every Python codebase assumes you have read. In practice you should let a formatter apply it for you, but read it once to understand what the formatter is doing and why.

  • CPython on GitHub github.com/python

    The interpreter itself, plus the issue tracker where the language's future is argued out in public. Worth opening once you are comfortable, if only to see that it is ordinary code written by people.

Sources & notes

  1. GitHub, Octoverse annual report. Python overtook JavaScript as the most-used language on GitHub by contributor count in the 2024 edition and held the position in 2025. github.blog/news-insights/octoverse
  2. TIOBE Programming Community Index, a search-volume based popularity measure — widely quoted, and widely criticised for its methodology. Python first reached first place in October 2021 and has held it since. tiobe.com/tiobe-index
  3. Python Package Index project count, shown on the PyPI home page. The index passed 500,000 projects in 2024 and has continued to grow; treat the figure here as a lower bound. pypi.org
  4. PEP 602, which moved CPython to an annual release cadence from version 3.9 onward: a feature release each October, then five years of support (roughly two of full fixes, three of security fixes only). peps.python.org/pep-0602
  5. Release and end-of-life dates throughout this site follow the official schedule PEPs and the CPython developer's guide version page.
